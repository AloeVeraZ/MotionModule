Hardware workbench

Hardware diagnostics

Every part, every connection, and the tools to make it work.

Before you connect anything: never run the 12 V battery rail or the servo V+ rail into a Raspberry Pi header pin. Keep the power rails fused and separate, join every supply negative at one common ground, and keep a physical cutoff in reach. Leave motor power switched off through boot until you have watched the outputs stay still.

Line the Pi up with the list

  1. Turn the Pi so its USB and Ethernet ports face down. The 40-pin header then runs down its right edge, as drawn.
  2. Pin 1 is the top pin of the row nearer the middle of the board. Pin 2 sits beside it, on the board’s edge.
  3. Odd pins run down the inner row and even pins down the outer row, so the list reads like the header itself: 1 and 2 at the top, 39 and 40 at the bottom.

02 / Motor drivers

Two motors per board.

Each dual H-bridge board takes four signal wires and a ground from the Pi, and drives two motors from the 12 V battery.

4 BOARDS · 8 MOTORS

Four dual H-bridge drivers

Configured · physical connection unverified

This is the motor driver MotionModule is built around. Each board runs two motors, and every pin is printed on the board:

IN1 · IN2
Drive MOTOR_A. MotionModule calls that output A, so on Driver 1 it is 1A.
IN3 · IN4
Drive MOTOR_B, output B: 1B on Driver 1. Drivers 2, 3 and 4 follow the same pattern.
GND
Joins a Pi ground pin so the signals share a reference. Motor current never flows through it.
VIN+ · VIN−
The 12 V battery; the board takes 3–18 V. Its inputs take 3–18 V signals too, so the Pi’s 3.3 V drives them directly.
Two inputs drive one motor
IN1 or IN3IN2 or IN4Motor
Speed signalOffForward
OffSpeed signalReverse
OffOffStopped, coasting

The speed signal is PWM: the pin switches on and off many times a second, and the share of time it is on sets the speed. Which way counts as forward depends on how the motor’s wires sit in its terminal, so flip it with inverted in hardware.py rather than rewiring.

Where each driver sits

The cards below are laid out like the reference controller plate: the Pi on the left with its USB ports at the bottom, Driver 1 beside those ports, Driver 2 above it, Driver 3 to the right of Driver 1 and Driver 4 above Driver 3. That is how the project’s Mecanum sample is wired, with its four wheels on Drivers 1 and 2. Wire the same way to run the sample unchanged, or change the pins in hardware.py to match your own wiring.

03 / Servo controller

Five wires. Sixteen servo outputs.

The Pi talks to one PCA9685 board over I²C and holds its output-enable pin. All five wires sit in one run on header pins 1–9, leaving pins 8 and 10 free for the serial console. Each servo plugs into a separate three-pin output on the board.

              motionmodule doctor
              
Checks the runtime, GPIO setup, I²C servo boards, and services without intentionally moving hardware.

              motionmodule restart
              
Stops outputs, reloads the active robot project, and starts it again.

            

            

              motionmodule logs
              
Follows the live service log so Python errors and startup messages are visible.

            

            

              motionmodule project list
              
Lists every robot project on the Pi; the active project has an asterisk.

            

            

              motionmodule project NAME
              
Activates another project folder and restarts MotionModule with that code.

            

            

              motionmodule versions
              
Lists installed MotionModule runtime versions without changing your robot code.

            

            

              motionmodule rollback
              
Returns to the previous runtime release while preserving every robot project.

Installs the sensor firmware on the Arduino GIGA plugged into the Pi, the same as Install firmware below. No Arduino IDE.

Which wheel is which?

          Enable Test Mecanum first · 50% power
        

        

          
Hold a button and watch which corner of the robot turns. The
            mix above only works if each channel really drives the corner it
            is named after.

          

          
Driving and strafing look correct even when
            two opposite corners are crossed — front‑left with
            rear‑right, or front‑right with rear‑left.
            Turning in place is the only move that shows it: the front pair
            fights the rear pair and the robot twitches instead of spinning.
            If a button turns the wrong corner, swap those two motors' leads
            at the driver board. Never change a pin.

What goes in the folder

                Download Mecanum sample
              

              

                

                  Required
                  MyRobot/robot.py
                  
The only file you must write. It defines
                    create_drive(module) and returns your robot
                    object.

                

                

                  Optional
                  MyRobot/hardware.py
                  
A copy of the pin file, with your own names. Leave it out
                    and the robot uses the names that ship with MotionModule
                    (driver_1a…driver_4b,
                    servo_0…servo_15).

                

                

                  Optional
                  MyRobot/dashboard.py
                  
Declares up to two camera feeds, one gyro/IMU, and up to
                    20 analog, digital, or text sensor readings. MotionModule
                    discovers it automatically.

                

                

                  Optional
                  MyRobot/anything_else.py
                  
More Python files for mechanisms, autonomous routines, and
                    helpers.

                

                
Only .py, .md,
                  .txt, and Arduino .ino files are accepted. MotionModule
                  checks every Python file and every pin before it replaces the
                  running project.

              

            


            

              

                
The shortest robot.py that works

                Download hardware.py
              

              

                

                  

class MyRobot:
    def __init__(self, module):
        self.module = module

    def drive(self, forward, strafe, rotate, speed=0.5):
        # forward, strafe and rotate are -1.0 to 1.0; rotate +1 turns left
        left = (forward - rotate) * speed
        right = (forward + rotate) * speed
        self.module.set_motors({
            "driver_1a": left,
            "driver_1b": left,
            "driver_2a": right,
            "driver_2b": right,
        })
        return {"left": left, "right": right}

    def stop(self):
        self.module.stop_all()


def create_drive(module):
    return MyRobot(module)

                

                
Save that as
                  robot.py inside a folder, choose the folder on
                  the left, and press Deploy and run. Names such as
                  driver_1a come from hardware.py; see
                  them all in Debug → Wiring.
