Hardware workbench

Hardware diagnostics

Every part, every connection, and the tools to make it work.

Before you connect anything: never run the 12 V battery rail or the servo V+ rail into a Raspberry Pi header pin. Keep the power rails fused and separate, join every supply negative at one common ground, and keep a physical cutoff in reach. Leave motor power switched off through boot until you have watched the outputs stay still.

Four dual H-bridge drivers

Configured · physical connection unverified

Each board controls two motors. IN1 and IN2 control direction and power. Driver 1 holds motor channels 1 and 2, driver 2 holds 3 and 4, and so on, with each driver’s four signal pins and its ground sitting together on the header.

02 / Servo controller

Five wires. Sixteen servo outputs.

The Pi talks to one PCA9685 board over I²C and holds its output-enable pin. All five wires sit in one run on header pins 1–9, leaving pins 8 and 10 free for the serial console. Each servo plugs into a separate three-pin output on the board.

Useful commands

Run from the web terminal or an admin SSH session
motionmodule doctor

Checks the runtime, GPIO setup, I²C servo boards, and services without intentionally moving hardware.

motionmodule pinout

Prints every motor name with its physical pin and GPIO wiring in the terminal.

motionmodule restart

Stops outputs, reloads the active robot project, and starts it again.

motionmodule logs

Follows the live service log so Python errors and startup messages are visible.

motionmodule project list

Lists every robot project on the Pi; the active project has an asterisk.

motionmodule project NAME

Activates another project folder and restarts MotionModule with that code.

motionmodule versions

Lists installed MotionModule runtime versions without changing your robot code.

motionmodule rollback

Returns to the previous runtime release while preserving every robot project.

How a command is built

Same shape for keys and sticks 
def drive(self, forward, strafe, rotate, speed=0.5):
    # forward  +1 ahead, -1 back      (left stick Y / W and S)
    # strafe   +1 right, -1 left      (left stick X / D and A)
    # rotate   +1 counter-clockwise   (right stick X / Q and E)
    # speed    0.0 to 1.0 limit from the slider
    ...

def controls(self):
    # optional: adds buttons and sliders to the Drive page
    return [{"name": "intake", "label": "Intake", "kind": "hold"}]

def control(self, name, value):
    if name == "intake":
        self.module.motor("driver_3a").set(value)

Both input methods call the same drive(), so code written for the keyboard works with a controller without changes.

What goes in the folder

Download Mecanum sample
Required MyRobot/robot.py

The only file you must write. It defines create_drive(module) and returns your robot object.

Optional MyRobot/hardware.py

A copy of the pin file, with your own names. Leave it out and the robot uses the names that ship with MotionModule (driver_1a…driver_4b, servo_0…servo_15).

Optional MyRobot/dashboard.py

Declares up to two camera feeds, one gyro/IMU, and up to 20 analog, digital, or text sensor readings. MotionModule discovers it automatically.

Optional MyRobot/anything_else.py

More Python files for mechanisms, autonomous routines, and helpers.

Only .py, .md, .txt, and Arduino .ino files are accepted. MotionModule checks every Python file and every pin before it replaces the running project.

The shortest robot.py that works

Download hardware.py 
class MyRobot:
    def __init__(self, module):
        self.module = module

    def drive(self, forward, strafe, rotate, speed=0.5):
        # forward, strafe and rotate are -1.0 to 1.0
        left = (forward + rotate) * speed
        right = (forward - rotate) * speed
        self.module.set_motors({
            "driver_1a": left,
            "driver_1b": left,
            "driver_2a": right,
            "driver_2b": right,
        })
        return {"left": left, "right": right}

    def stop(self):
        self.module.stop_all()


def create_drive(module):
    return MyRobot(module)

Save that as robot.py inside a folder, choose the folder on the left, and press Deploy and run. Names such as driver_1a come from hardware.py; see them all in Debug → Wiring.
