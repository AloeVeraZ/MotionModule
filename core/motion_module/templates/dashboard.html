Useful commands

Run from SSH, VS Code, or the web terminal
motionmodule doctor

Checks the runtime, GPIO setup, I²C servo boards, and services without intentionally moving hardware.

motionmodule pinout

Prints the complete physical-pin and GPIO wiring map in the terminal.

motionmodule restart

Stops outputs, reloads the active robot project, and starts it again.

motionmodule logs

Follows the live service log so Python errors and startup messages are visible.

motionmodule project list

Lists every robot project on the Pi; the active project has an asterisk.

motionmodule project NAME

Activates another project folder and restarts MotionModule with that code.

motionmodule versions

Lists installed MotionModule runtime versions without changing your robot code.

motionmodule rollback

Returns to the previous runtime release while preserving every robot project.

One editor · two connection modes

Code with VS Code

Use VS Code either directly on the Pi through Remote – SSH or in a local folder that you push to the robot. Only code installed on the robot is executed.

ACTIVE · {{ project_name }}
Both workflows use VS Code. Choose one for a project so you always know whether the newest copy is on your computer or already running on the robot.

Edit directly on the robot

VS Code Remote – SSH
Your exact connection values are filled in below. The username is the account created in Raspberry Pi Imager. The hostname is the robot name shown in Debug. Do not put the username before .local.
1 · Install the extension

Open Extensions in VS Code, search for Remote - SSH by Microsoft, and press Install.

2 · Add this Pi

Press Ctrl+Shift+P, choose Remote-SSH: Add New SSH Host…, paste the full command below, then choose the first SSH configuration file offered.

ssh YOUR_PI_USER@motionmodule.local
3 · Connect

Press Ctrl+Shift+P again, choose Remote-SSH: Connect to Host…, and select the robot. Choose Linux if asked, accept the fingerprint, then enter the Pi password from Raspberry Pi Imager.

4 · Open the robot folder

After the bottom-left corner says SSH: robot-name, choose File → Open Folder… and enter ~/MotionModule/robots/{{ project_name }}. Press OK and trust the folder.

5 · Run saved changes

Choose Terminal → New Terminal, run motionmodule restart, then run motionmodule logs to see Python errors.

If .local does not work: the school/router may block name discovery. Add the IP command below instead. It reaches the same Pi and uses the same username and password.

Edit locally, then push

VS Code local workspace
Open this repository in VS Code

Keep the MotionModule repository on your computer. Make a folder such as robots/MyRobot and copy examples/Mecanum into it as a starting point.

Code locally

Edit the local folder normally. Local changes do not move hardware and do not run on the robot.

Push and run

Choose Terminal → Run Task → MotionModule: Push robot project. Enter the local folder and the robot SSH target when prompted.

python tools/push_robot.py robots/MyRobot --host YOUR_PI_USER@motionmodule.local

The push validates every Python file, backs up an existing project, uploads the new folder, makes it active, and restarts MotionModule. That deployed copy is the one that runs.

Before driving

Safety
Use a physical motor-power cutoff. Browser control is for supervised testing, not a replacement for an emergency stop.
